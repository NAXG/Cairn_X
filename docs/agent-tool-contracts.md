# Agent 工具契约

## 模型可见参数

Cairn 自有工具提供对象参数 schema，并拒绝未声明的字段。参数说明重点描述
ID 的类型和范围、缺省行为、过滤器适用范围及分页续读规则；固定字面量不重复解释。
工具级描述保留用途、调用顺序、破坏性操作和不可信内容边界，避免重复字段说明。
PI 原生工具和插件自有工具沿用各自契约。

提示词负责角色、工作流程、证据判断与验收原则，不再重复参数枚举、JSON 编码、
过滤器和分页调用示例。Execute 运行时仍附加强制交付规则，但字段说明以工具为准。
Decide 保留执行结果状态的解释，因为它需要判断这些返回数据，且不装配 `submit_result`。

项目 `finding_schema` 保留在任务消息中，不动态扩展工具参数；`data_json` 仍由
服务端按项目契约校验。模型可见 schema 不能替代租约、权限和业务状态校验。

## 事实提交

`submit_fact`、Worker `/internal/executions/:id/facts` 和项目 `/projects/:id/facts`
均要求显式填写 `confidence`：`observed` 为直接观察，`inferred` 为推导判断。
缺失或无效值返回错误，不写入事实、不分配 ID。工具本地与服务端共用
`contracts/facts.ts` 的正文契约。项目起点事实仍由创建项目的控制面生成。

## 规划反馈

`signal_planner` 回执包含 `status`、`accepted`、`count` 和 `limit`：

| status          | 含义               | 执行者处理                                 |
| --------------- | ------------------ | ------------------------------------------ |
| `accepted`      | 新理由已记录       | 等待下一次可用规划，当前步骤继续执行       |
| `duplicate`     | 同一理由已经记录   | 不重复上报                                 |
| `limit_reached` | 本条新理由没有记录 | 提交支持事实，并在最终交付中说明未解决缺口 |

信号记录不承诺固定重规划时间；时机受租约、调度容量和冷却影响。达到上限后，
重复已记录的理由仍返回 `duplicate`，不再消耗额度。

## Finding 交付结构

Worker 领取的任务包含 `finding_schema`，没有结构定义时为 `null`。
Execute 首条任务消息携带完整 schema，与 Step 和来源事实并列，不依赖 Decide
在自由文本中转述，也不进入系统提示词。`submit_finding` 工具使用可选的 `data_json`
传递 JSON 文本，Worker 解析后仍通过 API 的 `data` 字段提交，由服务端按项目 schema
校验。对象、数组、字符串、数字、布尔及 null 均保留 JSON 类型；字符串载荷必须
包含 JSON 引号。无效 JSON 或旧工具字段 `data` 返回错误，不产生缺失载荷的 Finding。
步骤要求结构化交付时不能省略 `data_json` 或以正文代替；协议守卫同时适用于库内旧 prompt。
项目定义了非空 `finding_schema` 时，所有新 Finding 都必须显式提交载荷；Worker
在发送前拒绝缺失的 `data_json`，服务端同样拒绝缺失的 `data`。无 schema（包括
显式 null）仍允许纯文本 Finding。JSON null 是显式载荷，是否允许由 schema 决定。
任务消息按「Finding 契约 → 来源事实 → 当前步骤」排列，让跨步骤稳定内容处于前缀；
项目 schema 不改变工具参数定义。
结构描述属于数据，不能改变 Agent 的职责或权限。工具 schema 不随项目变化，保留提示词缓存。

## 工具错误语义

Cairn 自有工具返回 `details.error=true` 时，会通过 PI 的 `afterToolCall` 钩子设置
`isError=true`，并把正确状态传给原有插件结果钩子。模型仍收到原始可读错误，并可
修正参数重试；插件的内容、details、usage 等覆盖保持生效，但不能将已经发生的
Cairn 失败标成成功。PI 原生工具和插件自有工具沿用原有结果语义。

历史 Cairn 轨迹中，即使 PI 曾记录 `isError=false`，digest 也会读取显式的
`details.error=true`；此兼容只针对旧 Cairn 工具名，不从正文中的 ERROR 等字样推断失败。
重复信号、信号额度耗尽和错误 flag 等业务回执保持各自状态，不被统一计作工具执行失败。

## 收尾工具权限

探索阶段按配置加载工具。收尾阶段由会话框架的 `beforeToolCall` 执行允许名单：
内置 `read`、事实/成果/结果提交、规划信号、执行轨迹查询、评测状态与 flag 提交
可继续使用；环境修改、获取评测 Hint、重建靶机和未知插件工具均被拒绝。
允许名单还与本次运行实际装配的内置工具取交集；插件即使使用 `read` 等内置名称，
也不能冒充当前配置中未装配的内置工具。新增工具必须明确审核其收尾用途，不能
仅凭工具自述“只读”自动放行。

仅配置 bash、没有 read 的模式保留 bash 回看文件的例外；此时禁止环境修改依赖
提示词约束。该例外不会放行未知插件工具，标准模式仍禁止收尾调用 bash。
此处约束模型发起的工具调用，不将宿主进程中的可信插件代码描述为安全沙箱。

## 结果接收与持久化

`submit_result` 先校验并接收至 Worker 内存，回执明确表示本地接收、`persisted=false`，
然后触发收尾。运行器停止后统一请求持久化结果、用量及轨迹丢行统计，收到服务端
确认才认为已提交；失败沿用重试及失联处理。不得把本地回执当作已落库证明。

服务端与 Worker 应同步发布；缺少 `confidence` 的请求会被拒绝。
